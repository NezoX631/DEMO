# Инструкция по установке и запуску приложения ShoeStore

Настоящий документ содержит пошаговое руководство по развертыванию инфраструктуры базы данных и запуску десктопного приложения «Магазин обуви» (ShoeStore) из комплекта поставки.

## 1. Системные требования

- Операционная система: Windows 10 или Windows 11 (64-bit);
- Установленный и запущенный комплекс Docker Desktop с поддержкой контейнеров Linux (WSL 2);
- Плагин Docker Compose версии v2;
- Свободный локальный TCP-порт 5433 на хостовой системе.

> **Важно:** сервер СУБД PostgreSQL и среда Docker не упакованы внутрь исполняемого файла `ShoeStore.exe`. Исполняемый файл представляет собой клиентское приложение, которое подключается к серверной инфраструктуре по сетевому протоколу TCP/IP.

---

## 2. Развертывание серверной инфраструктуры (СУБД PostgreSQL)

Все файлы для управления контейнерами расположены в каталоге `deployment/`.

### Шаг 2.1. Настройка переменных окружения
1. Перейдите в каталог `deployment/`.
2. Скопируйте файл-шаблон `.env.example` в локальный файл `.env`:
   ```bash
   cp .env.example .env
   ```
3. При необходимости отредактируйте файл `.env`, задав собственный пароль:
   ```text
   POSTGRES_DB=shoe_store
   POSTGRES_USER=shoe_user
   POSTGRES_PASSWORD=your_secure_password
   POSTGRES_HOST_PORT=5433
   ```
   *(Файл `.env` содержит конфиденциальные учетные данные и не передается третьим лицам).*

### Шаг 2.2. Запуск контейнерного стека
Запустите сервисы базы данных и регламентной проверки в фоновом режиме:
```bash
docker compose up -d
```
Проверьте статус контейнеров:
```bash
docker compose ps
```
Контейнер базы данных `db` должен перейти в статус `healthy`.

### Шаг 2.3. Первичная инициализация схемы и данных
При первом запуске на чистом томе выполните перенос и импорт SQL-скрипта:
```bash
docker compose cp database/shoe_store.sql db:/tmp/shoe_store.sql
docker compose exec db psql -v ON_ERROR_STOP=1 -U shoe_user -d shoe_store -f /tmp/shoe_store.sql
```
*Примечание: если том `db_data` уже содержит заполненную базу данных, повторный импорт выполнять не требуется.*

## 3. Настройка и запуск десктопного приложения

Исполняемые файлы клиентской части находятся в каталоге `application/ShoeStore/`.

### Шаг 3.1. Создание файла конфигурации
1. В каталоге `application/ShoeStore/` (рядом с файлом `ShoeStore.exe`) создайте файл `config.ini` на основе шаблона `config.ini.example`.
2. Укажите параметры подключения к контейнеру:
   ```ini
   [database]
   host = 127.0.0.1
   port = 5433
   name = shoe_store
   user = shoe_user
   password = your_secure_password
   ```
   *Параметр `host` должен иметь значение `127.0.0.1`, а `port` соответствовать значению `POSTGRES_HOST_PORT` из файла `.env`.*

### Шаг 3.2. Запуск приложения
Запустите файл:
```bash
application/ShoeStore/ShoeStore.exe
```
При успешном подключении откроется главное окно каталога товаров компании «Чудо Обувь» с отображением карточек моделей, цен, скидок и изображений.

---

## 4. Остановка и возобновление работы

- **Приостановка работы (с сохранением состояния):**
  ```bash
  docker compose stop
  ```
- **Возобновление работы:**
  ```bash
  docker compose start
  ```
- **Предостережение:** не используйте команду `docker compose down -v`, так как она безвозвратно удаляет именованный том с файлами базы данных.

---

## 5. Диагностика неисправностей

| Симптом | Вероятная причина | Метод устранения |
|---|---|---|
| Ошибка подключения `connection timeout` | Контейнер СУБД остановлен или неверно указан порт | Проверьте статус `docker compose ps` и порт `5433` в файле `config.ini` |
| Ошибка аутентификации пользователя | Пароль в `config.ini` не совпадает с паролем в `.env` | Сверьте значение `POSTGRES_PASSWORD` в `.env` и пароль в `config.ini` |
| Не отображаются фотографии товаров | Папка `_internal` перемещена или повреждена | Запускайте `ShoeStore.exe` строго внутри его каталога со всеми библиотеками |
